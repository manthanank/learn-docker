25 Masterclass Questions
1. What is the fundamental architecture of an OCI container runtime (runc vs containerd vs dockerd)? ▼
Docker Engine Architecture:
  • dockerd: High-level daemon handling REST API, user authentication, image management, volume orchestration, and bridge networking.
  • containerd: Industry-standard container runtime supervisor (CNCF graduated). Manages complete container lifecycle, image pulls/pushes, and storage overlays.
  • containerd-shim: Sits between containerd and runc. Keeps STDIN/STDOUT FIFO open and allows dockerd/containerd restarts without terminating running containers.
  • runc: Low-level reference implementation of the OCI Runtime Specification. Uses clone(2) with namespace flags (CLONE_NEWPID, CLONE_NEWNS, etc.), configures cgroups in /sys/fs/cgroup, and calls pivot_root before executing PID 1. runc exits immediately after process handoff.
2. How does Linux Cgroups v2 differ from v1, and why is it critical for Kubernetes and container isolation? ▼
Cgroups v1 had disjoint, independent hierarchies for each controller (memory, cpu, blkio, pids) which caused deadlocks and synchronization flaws between memory writeback caching and blkio throttling.

Cgroups v2 introduces a unified single-hierarchy tree where controllers are enabled per cgroup. Key improvements include:
  • Accurate OOM killer scoping (kills the whole cgroup or single victim cleanly).
  • Integrated memory writeback and IO throttling.
  • Elimination of multiple hierarchy cross-deadlocks.
  • Pressure Stall Information (PSI) for memory, CPU, and IO starvation detection.
3. How does Overlay2 handle file deletion and directory replacement under the hood? ▼
Because lower layers are strictly read-only, Overlay2 cannot delete files from lower layers on disk. Instead:
  • Whiteout Files (.wh.): When a lower layer file is deleted, a character device node with major/minor number 0/0 is created in the UpperDir prefixed with .wh.. The overlay filesystem driver intercepts this and masks the underlying file from the Merged view.
  • Opaque Directories (.wh..wh..opq): When a directory is removed and recreated, Overlay2 sets an extended attribute or creates .wh..wh..opq inside the new directory in UpperDir, instructing the driver to hide all child files from underlying lower layers.
4. Why is running PID 1 in a container without an init system problematic (Zombie reaping and signal trapping)? ▼
In Unix, PID 1 has two unique kernel responsibilities:
  1. Signal Handling: The Linux kernel will not deliver default signal actions (like terminating on SIGTERM) to PID 1 unless the process has explicitly registered a custom signal handler. If Node.js, Python, or Java runs as PID 1 without signal traps, docker stop will hang for 10 seconds before being forcibly killed by SIGKILL (exit 137).
  2. Zombie Process Reaping: When child processes exit, they enter a zombie state until their parent calls wait(). If orphaned grandchildren exist, PID 1 adopts them. If PID 1 doesn't reap them, the PID table exhausts.
Remediation: Use docker run --init or lightweight inits like tini or dumb-init.
